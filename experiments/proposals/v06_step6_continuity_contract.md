# v0.6 step 6 — переемственность жизней: контракт (compact)

Доказываемая гипотеза: **смерть заканчивает жизнь персонажа, но не историю
мира.** Один мир, N последовательных жизней, идентичный результат
локально / через сокет / из реплея журнала. Архитектуру ядра не обсуждаем:
takeover целиком собирается из существующих механизмов.

## 1. Измеренные факты (сегодня, player_life, rng99-скрипт)

| мир | популяция t=100/200/300/400 | рождения | pool t600 | дети agent:0 | смерть agent:0 |
|---|---|---|---|---|---|
| seed7, 2×60 (нынешний E2E) | — /0/— | 1 | 59 | **0** | t51 |
| seed7, 4×50 | 47/18/1/0 | 4 | 46 | **0** | t48 |
| seed21, 4×50 | 56/60/35/17 | 36 | 14 | **0** | t203 |

Выводы, определяющие контракт:
- **Миры смертны.** При случайной политике без еды мир вымирает; seed21
  стабилен на «огоньках» (~16) с убывающим пулом. Игра окончима не
  смертью игрока, а вымиранием — это ставка, не баг.
- **Дети редки и лотерейны** (O1: родитель — случайный зрелый агент
  региона; за 200 тиков 36 рождений распределены по 25 родителям, игрок не
  получил ни одного). Наследник-ребёнок — событие удачи, не норма.
- **Пулу исчерпание — измеримая деградация** (47→14 за 600): мир конечен
  «по конструкции O5», режим `dormant_pool_ratio=1.0` делает династию
  окном, а не вечным циклом.

## 2. Модель: Мир ≠ Жизнь ≠ Сессия

- **Мир** = архив (`<db>.db`) + конфиг. Идентичность — meta
  (`seed, ruleset_version, …`), уже существующая. Один и только один
  активный писатель.
- **Жизнь** = сегмент `[T_начало, T_конец)` внутри мира: период, когда
  `PlayerAgentSystem.controlled = agent:M`. Конец: смерть (death) или
  лимит сессии (tick_limit).
- **Сессия** = период транспорта, управляющий одной жизнью: канал,
  `client_seq`, кадры. Смерть закрывает сессию (§6), но не архив и не
  результаты.
- Новая жизнь = **новая сессия на том же архиве**, никогда не новый мир;
  смерть не сбрасывает тики, не сбрасывает ids, не трогает прошлые жизни.

## 3. Takeover: как вторая жизнь продолжает первую без ядра

Механика (все части существуют, всё проверено шагом 3):

1. Открыть архив заново (`SqliteArchive` уже умеет reopen + append),
   прочитать расписание жизней **из самого журнала**: смены сущности
   `player.act` → список `(start_tick, agent)`. Никакого нового формата —
   граница жизни производна от истории, а не хранится рядом.
2. `create_world(тот же seed/ruleset/regions/agents, persist=None)` →
   replay: на каждом тике перед `step()` выставлять `system.controlled`
   по расписанию; канал получает ровно записанную ленту
   (`DecisionStreamReader`, выравнивание «одно действие на живой тик» —
   доказано bit-identical). Итог: состояние на head архива.
3. Передать сессии сим: `sim.journal = sim.index = archive`; жёсткий
   guard `takeover_mismatch` если `archive.max_id != sim._next_id-1`
   (продолжение id-нумерации — конструкцией, не соглашением).
4. Дальше — обычный `decide`-цикл. Тики (`state.tick`) продолжаются
   глобально; коллизии событий невозможны: один monotonный счётчик на мир.

Стоимость: O(history) реплея на каждую новую жизнь (минутный масштаб при
600 тиках). Снимки/инкрементальный takeover — сознательно отложены до P3
(профилирование решает, нужен ли он; контракт не блокирует).

Известный шероховатость для реализации: `hash()` reopened-архива пересчитан
с диска при новой записи — инкрементализировать (тот же канон, семантика не
меняется).

## 4. Преемственность (承 = рождение, не копирование)

Правило выбора наследника — чистая функция состояния мира на T_конец:

- **Основное**: живой потомок умершего — BFS по поколениям: дети
  (по `parent_id`), затем внуки…, внутри поколения — по `birth_tick`,
  затем id. Наследование фактов уже в мире: ребёнок унаследовал
  иммунитет/черты при рождении (step 2), живёт в регионе родителя, руины
  и поля — следы предка. **Никакого переноса состояния персонажа** (U-запрет).
- **Fallback (ратифицировать, Q1)**: потомков нет (типовой случай, §1) →
  наследник = **старейший живой агент мира** (min `birth_tick`, tie id),
  и takeover пишет в `meta` строку `life:<n>: {"agent":…, "succession":
  "elder"|"lineage"}`. meta — key-value идентичности, НЕ журнал: формат
  переходов не меняется (условие пользователя выполнено), а причина
  преемственности остаётся в архиве — AUTOPSY/карта следующей жизни могут
  сослаться.
- Нет ни потомков, ни живых агентов → `no_heir`: династия и игра окончены
  (мир = кладбище; `bio` последнего поколения доступен). Это конец, его не
  обходят: см. §5.

## 5. Исчерпание пула = потолок мира (решение, не ошибка)

- `free_dormant == 0` уже семантика O5: «carrying capacity reached».
  В v0 **регенерации пула нет** — и не предвидится: возобновляемый пул
  превратил бы «compost world» (конечность кормит потомков) в вечный
  воспроизводственный цикл и украл у игры ставки. Позиция пользователя
  ратифицируется данными: убывающий пул (47→14) — работающий механизм.
- Истощение пула ≠ конец династии напрямую: дети рождаются и без пула?
  нет — рождение требует свободный слот; значит пул есть бюджет всего
  биологического будущего мира. Числа бюджета — в профиле P3.

## 6. Протокол — дельта к v0 (иначе всё без изменений)

- `hello {world:"name"}` при создании/возобновлении сессии; серверный
  db_dir + name = путь (клиент не передаёт пути — авторитет сервера).
- `{world, new_life:true}` → takeover: создать/присоединить мир,
  выбрать наследника (§4), `welcome` несёт `life:{n, agent, succession,
  from_tick}` + обычный набор.
- Ошибка `world_busy` (активная сессия на мире — в т.ч. между смертью и
  close: см. ниже), `no_heir`, `takeover_mismatch`.
- Жизненный цикл уточнён: **смерть ⇒ сервер сам финализирует сессию**
  (flush+close) сразу после `finished`. Иначе смерть висила бы открытым
  писателем и блокировала `world_busy` для следующей жизни. Результаты
  после close живы (спека §4 — bio/autopsy из файла).
- `close {}` идемпотентен, `bio {agent?}`, `autopsy` — без изменений;
  карточка жизни = существующий `build_biography(db, agent:M)`.
  Границы жизни в карте: лента решений сама несёт `first/last_tick`;
  meta-диапазон остаётся архивным (чистота карты, Q3).

## 7. Критерии приёмки (тесты, затем ручная дорожка)

Мир приёмки: **seed21, regions=4, agents=50** — жизни короткие, вымирание
реальное, все три исхода достижимы естественным путём.

1. Три жизни через `Session` подряд (L1 death → takeover L2 elder → L3):
   journal id-непрерывен (0 gap), `tick_range` монотонен, три fingerprint
   карточек стабильны; в meta строки `life:1..3` c `succession`.
2. P1 поперёк takeover: тот же поток, локально vs WS (3 сессии-жизни,
   реконнект в середине) → **identical `journal.hash()` и fingerprint
   каждой жизни**.
3. **Реплей-само-доказательство**: восстановить весь многожизненный мир из
   его архива (реплей §3), подать ему выведенные из журнала ленты →
   финальный хэш идентичен. (Доказывает: takeover-расписание производно от
   истории; второй версии истории нет.)
4. `world_busy` до close, `no_heir` на вымершем мире, `takeover_mismatch`
   на подменённом конфиге — каждое отказывает без шага мира.
5. Ручная дорожка: `serve` + `play` дважды: первая жизнь умирает, команда
   `new-life` в клиенте → вторая стартует с наследником, bio обеих печатается.

## 8. Ратифицировать / отложить

Открытые вопросы (рекомендации даны; без ответов §4–§6 не пишем код):
- **Q1** fallback-наследник «старейший» vs строгая династия (иначе ~1 жизнь
  на мир — при данных §1 игра многими жизнями станет экзистенциальной
  удачей; рекомендация: elder + запись в meta, честная и различимая).
- **Q2** авто-close на смерти (рекомендация: да — снимает world_busy и
  делает «смерть = граница жизни» физическим фактом архива).
- **Q3** границы жизни в карте: оставляем производными от ленты решений
  (рекомендация) vs отдельный запрос к архиву за первой/последней смертью
  — v1 карты не расширяем.
- **Q4** именование миров: `name` → `<db_dir>/<name>.db` (рекомендация) vs
  клиентский путь (ломает авторитет сервера).

Заранее запрещено/отложено: регенерация пула; snapshot/takeover из
состояния (до P3); параллельные сессии на мире; перенос полей персонажа
(«наследство состоянием»); auto-tick мира между жизнями (мир живёт, только
когда в него играют — синхронность Q2 без исключений); Rust.

## 9. Ратификация (решения пользователя, обязательны к исполнению)

Q1–Q4 приняты с уточнениями:

- **Q1**: elder-fallback одобрен, но elder — **преемник управления, не
  родственник**: интерфейс (welcome.life, meta) несёт `succession:
  "lineage"|"elder"|"genesis"` и не выдаёт elder за кровного. Выбор
  потомка — фиксированный BFS-порядок (поколение, `birth_tick`, id), не
  порядок обхода коллекции.
- **Q2**: смерть ⇒ flush+close; close НЕ удаляет сессию из реестра —
  результаты (bio/autopsy) остаются доступны через неё же (state=
  finalized). **Смерть агента ≠ вымирание мира**: первое завершает жизнь,
  второе — невозможность следующей (no_heir terminal).
- **Q3**: таблица жизней не вводится; но **границы — не из наличия
  первого/последнего действия**: каждый life регистрируется строкой в
  meta `{agent, from_tick, succession, end, to_tick, decisions}`, где
  `end ∈ {death, abdicate, tick_limit}` и `decisions:int`. Пустой сегмент
  (decisions=0, end=abdicate), незавершённая жизнь и последняя смерть
  различимы явно. Последовательность `player.act` — только перекрёстная
  проверка расписания (guard `takeover_mismatch`).
- **Q4**: имя мира — строгий идентификатор (`^[a-z0-9][a-z0-9_-]{0,31}$`),
  не путь: ни разделителей, ни расширений, ни `..`; сервер сам собирает
  `<db_dir>/<name>.db`.

Две обязательные проверки (до/при реализации):

1. **Takeover не зависит от скрытого состояния прошлых сессий.** Критерий
   приёмки: после реплея архива совпадают (а) канонический `state.hash()`
   целиком — RNG-адресуемость, dormant-пул, поколения, руины, все поля, и
   (б) `journal.hash()` воспроизведённой истории против архива. Лента
   решений обязана быть достаточной для ПОЛНОГО восстановления, а не
   только списка жизней. Закрепляется постоянным тестом.
2. **`no_heir` терминален**: нет пополнения пула, нет перезапуска, нет
   тихого создания нового архива (тест сверяет каталог до/после).

Протокол уточнён: `hello {world}` сам достаточен — файла нет → новая жизнь
1; файл есть → следующая жизнь по правилу §4. Флаг `new_life` убран.
`finished` несёт `life`, `bio_fingerprint`, `autopsy`-ядро (смерть
авто-финализирует писателя, сессия остаётся для результатов). `world_busy`
снимается resume+close зависшей сессии — обходной путь документирован.
Инкрементализация `hash()` отложена на P3 (решение пользователя).
