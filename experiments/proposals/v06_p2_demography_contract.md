# v0.6 P2 — контракт калибровки демографии (проект; критерии ждут ратификации)

Вопрос P2 — не «как сделать мир бессмертным», а **какой горизонт и характер
демографической динамики нужны CAUSAL как игре**. Пока критерии не ратифицированы,
параметры правил не меняются; этот шаг — только измерения и определения.

## 0. Границы и non-goals

- Калибровка возможна **только в игровом ruleset** (`player_life`). Исследовательские
  мирки заморожены: пин-тесты хэшей v0.2 остаются обязательными, любые изменения
  general-ruleset'ов — вне P2.
- Регенерация пула dormant-слотов — **заранее отвергнута** (решение шага 6):
  численность за всю жизнь мира ограничена `agents` слотами, и это архитектурный
  факт дизайна, а не баг. P2 обязан показать, связывает этот потолок игру или нет.
- Снимки состояния, формат архива, протокол — вне P2.
- Вымирание — свойство модели, подлежащее измерению, а не «ошибка для починки».

## 1. Определения исходов (не сводить к одному «мир жив/мёртв»)

Для каждого прогона фиксируются РАЗНЫЕ события:

| код | определение |
|---|---|
| `player_death` | контролируемый агент умер; мир продолжает (старейшина/линия наследует) |
| `heir_break` | нет живого кандидата (ни elder, ни lineage) при ЖИВЫХ агентах в мире — прервана преемственность, мир не вымер |
| `extinction` | `alive_count == 0` — мир вымер (heir_break с alive=0 классифицируется именно так) |
| `pool_exhausted` | момент, когда свободных dormant-слотов больше нет (struct ceiling; мир может жить) |
| `food/soil collapse` | популяция ниже доли стартовой дольше K тиков без возврата (определяемо по кривой) |
| `tick_limit` | достижение лимита прогона при живом мире (не событие мира!) |

## 2. Метрики (на прогон) и статистика (по семенам)

На прогон: `first_birth_tick`, `births_total`, `deaths_total`, посистемные причины
смертей (`alive→false` writes), кривая `population(t)`, `pop_min/final/median`,
`extinction_tick?`, `pool_exhausted_tick?`, `heir_break_tick?`; для сессионной
панели: длины жизней (t), число смен власти, исход.
По семенам (n≥12): медиана + IQR + min/max КАЖДОЙ метрики. Разброс — предмет
калибровки, а не шум: мир без разброса — не игра.

## 3. Протогонная методология

- Панель A (свойства правил, без игрока): `player_life`, 4 региона × 50 слотов,
  cap 1500 тиков, seeds 0..11, memory journal, детерминизм-фингерпринт на прогон.
- Панель B (игрок и преемственность): тот же мир через Session (скрипт-стрим),
  cap 12 жизней × 150 решений; исходы по §1.
- Панель C (контроль research): `research_world`, те же seeds — база сравнения,
  доказывающая, что игровая динамика отличается от исследовательской ЦЕЛИКОМ,
  и что мы её не трогаем.
- Все прогоны воспроизводимы seed'ом; данные и скрипт коммитятся (JSON рядом).

## 4. Кандидатские критерии приёмки (НА РУТИФИКАЦИЮ — цифры предложены, не приняты)

Базовая линия ниже (п.5) — отправная точка; цели формулируются «горизонт + характер»:

1. **Горизонт**: ≥80 % seed'ов панели A доживают до 1500 тиков с населением
   ≥ 20 % от стартового (ныне: вымирание/истощение раньше — см. данные).
2. **Поколения**: ≥ 3 смены живого поколения (births у детей рождёвших) к моменту
   горизонта хотя бы на половине seed'ов — мир переживает поколения, а не только
   основателей.
3. **Динамика, а не плато**: амплитуда pop(t) после 200-тикового прогрева
   находится в коридоре (не монотонное сползание к 0 и не взрыв к потолку слотов)
   — формально: 0.15·N ≤ pop(t) ≤ 0.85·N для ≥ 60 % тиков после прогрева.
4. **Пулы**: `pool_exhausted` НЕ наступает раньше горизонта на ≥ 80 % seed'ов
   (иначе потолок слотов — маскирует демографию; тогда этоgame-design решение,
   вынесенное отдельно).
5. **Игрок**: панель B — медиана длины жизни ≥ 100 тиков; `heir_break` при живых
   агентах (прерывание линии без вымирания мира) — редок: ≤ 1 из 12 seed'ов;
   полное вымирание до cap — НЕ считаем ошибкой, но его медианный срок ≥ horizon/2.
6. **Research-инвариант**: панель C побайтово не меняется НИКОГДА (пин-хэши).

Порядок работ после ратификации: один параметрический проход (fertility/смертность
`player_life`), те же панели, те же критерии, сравнение таблиц, ни одного
одновременного изменения формата/протокола.

## 5. Базовая линия (измерена этим контрактом, до любых изменений)

`experiments/p2_demography_baseline.py` → `p2_demography_baseline.json`
(12 seeds, 4 региона × 50 genesis + 50 dormant слотов, cap 1500,
2026-10-14). Ключевые числа:

**Панель A — характер правил без игрока.** Вымирание **12/12** до cap'а,
экстинкция на T = 298..872 (медиана 723). Смерти стабильно больше рождений
(медиана: births 29, deaths 79) — монотонный спуск, плато нет. Причины
смертей: старение доминирует (seed 1: Senescence 93, AgentSystem 7 — еда).
**Два разных механизма отказа**: на 8/12 seed'ов мир гаснет, когда пул ещё
свободен (dormant_at_extinction 20..47 — некому рожать, потолок не виновен);
на 4/12 пул исчерпывается раньше (T≈406..595), и дальше смерти нечем
замещать. Рождения стартуют рано (первый child T 22..64).

**Панель B — игрок и преемственность.** Жизней на мир: 3..12 (медиана 9);
смертей игрока: 77; длина жизни: 1..150 тиков (медиана 82, Q1 27.5 — половина
жизней коротка). Исходы разделены честно: `extinction` (мир вымер вместе с
линией) 10/12; `world_alive_at_cap` (chain cap батареи, мир жив) 2/12;
`heir_break` (линия рвётся при живом мире) **0/12** — механизм шага 6 здоров,
преемственность не тоньше демографии.

**Панель C — замороженный контроль.** research-миры: births 0 by design,
вымирание 12/12 (медиана 566). Демографическая дельта игры целиком来自
рождающего контура `player_life` — калибровка законно живёт только там.

**Выводы для ратификации критериев (§4):**
1. Текущий игровой горизонт ≈ «полтора-два часа решений» и кончается всегда;
   если игра хочет «десятки поколений», нужен калибровочный проход
   (баланс fertility/mortality), а не только увеличение `agents`.
2. Увеличение пула слотов лечит 4/12 seed'ов (режим отказа 2), но не 8/12
   (режим отказа 1: нет родителей) — критерий 4 про пулы по данным осмыслен.
3. Разброс огромен (T 298..872) — критерии обязаны быть перцентильными,
   «средний мир» не существует.
4. Короткие жизни игрока (медиана 82 тика, минимум 1) — кандидат на
   отдельное проектное решение (min-lifespan в ruleset), не побочный эффект.
5. `heir_break == 0` подтверждает: сначала демография, снапшоты не нужны.
